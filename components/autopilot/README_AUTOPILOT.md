## Компонент «Автопилот» агродрона

Этот документ описывает, **как другим компонентам системы взаимодействовать с автопилотом** через брокер сообщений.

Формат имён топиков для всех компонентов дрона:

- `agrodron.<имя_компонента>.<подсистема>`

Для автопилота используется префикс `agrodron.autopilot.*`.

---

## 1. Назначение компонента

- Принимает **подготовленную миссию** от обработчика миссий.
- Поддерживает **жизненный цикл миссии**: загрузка, запуск, пауза, возобновление, завершение, отмена.
- Выполняет миссию, **используя навигационные данные**.
- Управляет движением дрона и опрыскивателем, публикуя команды в топик:
  - `agrodron.autopilot.actuators`
- По запросу отдаёт **состояние миссии и автопилота**.
- **Не обрабатывает аварийные ситуации** – в случае аварии внешние компоненты могут отключить автопилот от брокера или не отправлять ему данные.

---

## 2. Топики автопилота

### 2.1. Входящие топики (на которые подписывается автопилот)

#### 2.1.1. Миссия

- **Топик**: `agrodron.autopilot.mission`
- **Кто пишет**: обработчик миссий.
- **Кто читает**: автопилот.
- **Назначение**: загрузка новой миссии.

Сообщение:

```json
{
  "action": "MISSION_LOAD",
  "mission": {
    "mission_id": "string",
    "steps": [
      {
        "id": "wp-001",
        "lat": 60.123456,
        "lon": 30.123456,
        "alt_m": 5.0,
        "speed_mps": 5.0,
        "spray": true
      }
    ]
  }
}
```

> Обработчик миссий конвертирует входной формат (например, WPL) в этот простой JSON.

#### 2.1.2. Команды оператора

- **Топик**: `agrodron.autopilot.command`
- **Кто пишет**: интерфейс оператора / наземная станция управления, а также система ОРВД.
- **Кто читает**: автопилот.
- **Назначение**: управление жизненным циклом миссии.

Сообщение (общий формат):

```json
{
  "action": "CMD",
  "sender": "GCS",        // GCS (наземная станция) | ATC (ОРВД)
  "command": "START",     // START | PAUSE | RESUME | ABORT | RESET | EMERGENCY_STOP | KOVER
  "mission_id": "string", // для START/RESET (опционально)
  "reason": "operator_request"
}
```

Автопилот интерпретирует команды так:

- `START` – начать выполнение загруженной миссии.
- `PAUSE` – приостановить выполнение (дрон переходит в безопасный статичный режим, опрыскиватель выключен).
- `RESUME` – продолжить с текущего шага, если всё в норме.
- `ABORT` – штатно прервать миссию, перейти в состояние «отменена».
- `RESET` – сбросить текущее состояние автопилота в «IDLE` (без аварийной логики).
- `EMERGENCY_STOP` – перевести автопилот в состояние `EMERGENCY_STOP`, он перестаёт отдавать команды в `actuators`.
- `KOVER` – команда «Ковер» от ОРВД: немедленно прекратить выполнение миссии и перейти в режим вынужденной посадки / ожидания возобновления по политике системы (логика посадки реализуется вне автопилота, но автопилот более не выдаёт управляющие команды).

Требование приоритета:

- Команды с `sender = "ATC"` (ОРВД) **имеют приоритет** над командами с `sender = "GCS"` (наземная станция).
- При конфликте (например, `KOVER` от ОРВД и `RESUME` от земли) автопилот должен обрабатывать команды ОРВД и игнорировать противоречащие им команды от наземной станции до снятия ограничения.

#### 2.1.3. Навигация

- **Топик**: `agrodron.navigation.state`
- **Кто пишет**: компонент навигации.
- **Кто читает**: автопилот (подписывается на этот внешний топик).
- **Назначение**: периодическая передача навигационного решения.

Навигация получает «сырые» данные (например, NMEA-0183) и публикует удобный JSON:

```json
{
  "action": "NAV_STATE",
  "timestamp": "2026-03-09T12:00:01.234Z",
  "lat": 60.123450,
  "lon": 30.123400,
  "alt_m": 4.9,
  "ground_speed_mps": 4.8,
  "heading_deg": 90.0,
  "fix": "3D",        // NONE | 2D | 3D
  "satellites": 14,
  "hdop": 0.7
}
```

Частота публикации – 5–20 Гц (настраивается в компоненте навигации).

#### 2.1.4. Запросы телеметрии

- **Топик**: `agrodron.autopilot.telemetry`
- **Кто пишет**: телеметрия, мониторинг, интерфейс оператора (любой компонент, которому нужна информация).
- **Кто читает**: автопилот.
- **Назначение**: запрос текущего состояния автопилота/миссии.

Важный принцип: **автопилот сам по себе ничего не шлёт** – он отвечает только на запросы.

Формат запроса:

```json
{
  "direction": "REQUEST",
  "request_id": "uuid-1234",
  "action": "GET_STATE"
}
```

---

### 2.2. Исходящие топики (которые заполняет автопилот)

#### 2.2.1. Команды приводам и опрыскивателю

- **Топик**: `agrodron.autopilot.actuators`
- **Кто пишет**: автопилот.
- **Кто читает**: приводы, опрыскиватель.
- **Назначение**: передача текущей команды движения и состояния сброса.

В этом топике разделение по полю `action`:

```json
{
  "action": "DRIVE_COMMAND",
  "timestamp": "2026-03-09T12:00:01.250Z",
  "mission_id": "mission-1",
  "mode": "AUTO",
  "target": {
    "heading_deg": 90.0,
    "ground_speed_mps": 5.0,
    "alt_m": 5.0
  }
}
```

```json
{
  "action": "SPRAYER_COMMAND",
  "timestamp": "2026-03-09T12:00:01.250Z",
  "mission_id": "mission-1",
  "spray": true,
  "rate_lpm": 2.0
}
```

- Компонент **приводов** фильтрует сообщения с `action = "DRIVE_COMMAND"`.
- Компонент **опрыскивателя** фильтрует сообщения с `action = "SPRAYER_COMMAND"`.

Частота публикации DRIVE-команд – 10–50 Гц (настраивается в автопилоте).  
SPRAYER-команды можно отправлять реже – при изменении состояния или с низкой частотой.

#### 2.2.2. Ответы на запросы телеметрии

- **Топик**: тот же, что и для запросов, `agrodron.autopilot.telemetry`.
- **Кто пишет**: автопилот.
- **Кто читает**: все заинтересованные компоненты.
- **Назначение**: разовый «снимок» состояния автопилота и миссии.

Формат ответа:

```json
{
  "direction": "RESPONSE",
  "request_id": "uuid-1234",
  "action": "STATE",
  "mission_id": "mission-1",
  "state": "EXECUTING",          // IDLE | MISSION_LOADED | PREPARE | EXECUTING | PAUSED | COMPLETED | ABORTED | EMERGENCY_STOP | ERROR
  "current_step_id": "wp-001",
  "progress": {
    "completed_steps": 3,
    "total_steps": 20
  },
  "sprayer_state": "ON"          // ON | OFF
}
```

Компонент телеметрии организует цикл запросов (например, раз в 0.5–1 секунду) и по `request_id` сопоставляет ответ.

## 3. Формат миссии для автопилота (JSON)

Автопилот работает с **упрощённым форматом** миссии. Основная цель – удобство реализации и тестирования в SITL.

Пример миссии:

```json
{
  "mission_id": "mission-1",
  "home": {
    "lat": 60.000000,
    "lon": 30.000000,
    "alt_m": 0.0
  },
  "steps": [
    {
      "id": "wp-001",
      "type": "WAYPOINT",      // пока достаточно WAYPOINT
      "lat": 60.123456,
      "lon": 30.123456,
      "alt_m": 5.0,
      "speed_mps": 5.0,
      "spray": false
    },
    {
      "id": "wp-002",
      "type": "WAYPOINT",
      "lat": 60.123500,
      "lon": 30.123800,
      "alt_m": 5.0,
      "speed_mps": 5.0,
      "spray": true
    }
  ]
}
```

Минимально обязательные поля для шага:

- `id` – строковый идентификатор шага.
- `type` – пока достаточно `WAYPOINT`.
- `lat`, `lon` – координаты в градусах (WGS84).
- `alt_m` – высота в метрах над уровнем моря или относительно home (решается на стороне навигации/СИТЛ).
- `speed_mps` – желаемая скорость.
- `spray` – флаг включения опрыскивателя **на отрезке до следующей точки**.

Все дополнительные «красивые» фичи (типы точек, длительность зависания и т.п.) можно добавить позже.

## 4. Формат навигационных данных (JSON)

Компонент навигации делает преобразование **NMEA‑0183 → JSON** и отправляет результат в `agrodron.navigation.state`.

Рекомендуемый минимальный формат:

```json
{
  "action": "NAV_STATE",
  "timestamp": "2026-03-09T12:00:01.234Z",
  "lat": 60.123450,
  "lon": 30.123400,
  "alt_m": 4.9,
  "ground_speed_mps": 4.8,
  "heading_deg": 90.0,
  "fix": "3D",        // NONE | 2D | 3D
  "satellites": 14,
  "hdop": 0.7
}
```

Этого достаточно, чтобы автопилот:

- определял текущее положение относительно целевой точки;
- рассчитывал курс, высоту и скорость;
- контролировал качество навигации (по `fix`, `satellites`, `hdop`).

---

## 5. Кратко: кто с чем работает

- **Обработчик миссий**:
  - Пишет в `agrodron.autopilot.mission` (формат миссии из раздела 3).

- **Операторский интерфейс / надсистема**:
  - Пишет в `agrodron.autopilot.command` (команды управления миссией).
  - Может читать ответы в `agrodron.autopilot.telemetry`.

- **Навигация**:
  - Пишет в `agrodron.navigation.state` (упрощённые навигационные данные).

- **Приводы**:
  - Читают `agrodron.autopilot.actuators` с `action = "DRIVE_COMMAND"`.

- **Опрыскиватель**:
  - Читает `agrodron.autopilot.actuators` с `action = "SPRAYER_COMMAND"`.

- **Телеметрия / мониторинг**:
  - Пишут запросы в `agrodron.autopilot.telemetry` (`GET_STATE`).
  - Читают ответы из того же топика (`STATE`).

Этого документа достаточно, чтобы разработчики соседних компонентов могли настроить обмен сообщениями с автопилотом в общем брокере.
