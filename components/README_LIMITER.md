## Компонент «Ограничитель» агродрона

Этот документ описывает, **как другим компонентам системы взаимодействовать с ограничителем** через брокер сообщений.

Формат имён топиков в системе:

- `agrodron.<имя_компонента>.<подсистема>`

Для ограничителя используется префикс `agrodron.limiter.*`.

---

## 1. Назначение компонента

- Контролировать, **не нарушает ли текущая миссия заданные ограничения** (отклонение от маршрута, нарушенные зоны и т.п.).
- Анализировать:
  - текущие навигационные данные;
  - состояние моторов и опрыскивателя;
  - информацию о текущей миссии и её шагах.
- При обнаружении отклонений выше допустимых порогов:
  - **запускать протокол аварийной посадки**, формируя соответствующее событие;
  - дальше работу выполняет отдельный компонент (например, аварийный контроллер/экстренная ситуация).

Сам ограничитель **не управляет приводами и опрыскивателем напрямую**, он только:

- наблюдает за выполнением миссии;
- публикует события нарушений/запуска посадки.

---

## 2. Используемые форматы данных

Ограничитель использует те же форматы, что и автопилот.

### 2.1. Формат миссии

Формат миссии идентичен формату, который получает автопилот:

```json
{
  "mission_id": "mission-1",
  "home": {
    "lat": 60.000000,
    "lon": 30.000000,
    "alt_m": 0.0
  },
  "steps": [
    {
      "id": "wp-001",
      "type": "WAYPOINT",
      "lat": 60.123456,
      "lon": 30.123456,
      "alt_m": 5.0,
      "speed_mps": 5.0,
      "spray": false
    },
    {
      "id": "wp-002",
      "type": "WAYPOINT",
      "lat": 60.123500,
      "lon": 30.123800,
      "alt_m": 5.0,
      "speed_mps": 5.0,
      "spray": true
    }
  ]
}
```

Ограничитель может получать миссию либо:

- из того же топика, что и автопилот (`agrodron.autopilot.mission`);
- либо из отдельного служебного топика (`agrodron.limiter.mission`), если так будет удобнее интеграции.

### 2.2. Формат навигационных данных

Ограничитель использует JSON, формируемый навигацией:

```json
{
  "action": "NAV_STATE",
  "timestamp": "2026-03-09T12:00:01.234Z",
  "lat": 60.123450,
  "lon": 30.123400,
  "alt_m": 4.9,
  "ground_speed_mps": 4.8,
  "heading_deg": 90.0,
  "fix": "3D",
  "satellites": 14,
  "hdop": 0.7
}
```

Эти сообщения публикуются навигацией в топик:

- `agrodron.navigation.state`

Ограничитель, как и автопилот, **подписывается** на этот топик.

### 2.3. Состояние моторов и опрыскивателя

Ограничитель **не взаимодействует напрямую** с моторами и опрыскивателем и не подписывается на их внутренние топики.

Для анализа он использует **агрегированное состояние дрона**, которое предоставляет компонент телеметрии.

Рекомендуется единый JSON-формат, публикуемый телеметрией, например в топик:

- `agrodron.telemetry.state`

Пример агрегированного состояния:

```json
{
  "timestamp": "2026-03-09T12:00:01.260Z",
  "mission_id": "mission-1",
  "autopilot_state": "EXECUTING",
  "motors": {
    "mode": "AUTO",
    "target": {
      "heading_deg": 90.0,
      "ground_speed_mps": 5.0,
      "alt_m": 5.0
    }
  },
  "sprayer": {
    "spray": true,
    "rate_lpm": 2.0
  }
}
```

Именно эти данные (через телеметрию) ограничитель использует вместе с навигацией и миссией для принятия решения о нарушении ограничений.

## 3. Топики ограничителя

### 3.1. Входящие топики (на которые подписывается ограничитель)

1. **Навигация**

   - Топик: `agrodron.navigation.state`
   - Кто пишет: компонент навигации.
   - Назначение: текущие координаты, скорость, курс – для определения, насколько дрон следует миссии.

2. **Миссия**

   Варианты:

   - Подписка на `agrodron.autopilot.mission` (ограничитель получает ту же миссию, что и автопилот).
   - Либо выделенный топик `agrodron.limiter.mission`, если архитектурно будет удобнее дублировать миссию.

3. **Агрегированная телеметрия**

   - Топик: `agrodron.telemetry.state`
   - Кто пишет: компонент телеметрии.
   - Назначение: сводное состояние дрона (моторов, опрыскивателя, автопилота и др.), используемое ограничителем для анализа.

4. **Параметры ограничений (опционально)**

   - Топик: `agrodron.limiter.config`
   - Кто пишет: конфигурационный сервис / оператор.
   - Назначение: передача порогов:
     - допустимое отклонение от линии/точки по горизонтали;
     - допустимые отклонения по высоте;
     - специальные зоны запрета (если нужны).

   Пример:

   ```json
   {
     "max_distance_from_path_m": 10.0,
     "max_alt_deviation_m": 3.0
   }
   ```

### 3.2. Исходящие топики (которые заполняет ограничитель)

1. **События нарушений и аварийной посадки**

   - Топик: `agrodron.limiter.event`
   - Кто пишет: ограничитель.
   - Кто читает: компонент аварийной посадки / экстренной ситуации, система мониторинга.

   Примеры сообщений:

   ```json
   {
     "timestamp": "2026-03-09T12:00:02.000Z",
     "mission_id": "mission-1",
     "event": "DEVIATION_WARNING",
     "details": {
       "distance_from_path_m": 8.5,
       "max_distance_from_path_m": 10.0
     }
   }
   ```

   ```json
   {
     "timestamp": "2026-03-09T12:00:03.000Z",
     "mission_id": "mission-1",
     "event": "EMERGENCY_LAND_REQUIRED",
     "reason": "DISTANCE_FROM_PATH_EXCEEDED",
     "details": {
       "distance_from_path_m": 15.0,
       "max_distance_from_path_m": 10.0
     }
   }
   ```

   - Событие `EMERGENCY_LAND_REQUIRED` трактуется как **запрос запуска протокола аварийной посадки**.
   - Реальное выполнение посадки делает другой компонент, ограничитель только инициирует.

2. **Собственный статус ограничителя (опционально)**

   - Топик: `agrodron.limiter.state`
   - Кто пишет: ограничитель.
   - Кто читает: телеметрия, мониторинг.

   Пример:

   ```json
   {
     "timestamp": "2026-03-09T12:00:01.500Z",
     "state": "NORMAL",           // NORMAL | WARNING | EMERGENCY
     "last_event": "NONE"
   }
   ```

---

## 4. Логика работы ограничителя (в общих чертах)

1. **Получение миссии**
   - Ограничитель получает и сохраняет миссию.
   - Строит внутреннее представление траектории (последовательность точек).

2. **Наблюдение за полётом**
   - На каждом обновлении навигации:
     - определяет текущий активный шаг миссии (точку/отрезок);
     - вычисляет расстояние от фактического положения до:
       - ближайшей точки маршрута;
       - или до идеальной линии между текущей и следующей точкой.
   - Сравнивает расстояние и высоту с допустимыми порогами.

3. **Пороги и реакции**
   - Если отклонение **меньше порога предупреждения** – состояние `NORMAL`.
   - Если отклонение **между порогом предупреждения и аварийным порогом** – может публиковаться `DEVIATION_WARNING`.
   - Если отклонение **превышает аварийный порог**:
     - публикуется событие `EMERGENCY_LAND_REQUIRED`;
     - состояние становится `EMERGENCY`.

4. **Взаимодействие с другими компонентами**
   - Компонент аварийной посадки / экстренной ситуации подписывается на `agrodron.limiter.event` и реализует:
     - остановку миссии;
     - посадку или другой сценарий.
   - Автопилот может использовать эти события только как информационные (логика аварийной посадки у вас уже вынесена в другие модули).

---

## 5. Кратко: кто с чем работает

- **Навигация**:
  - Пишет в `agrodron.navigation.state`.
  - Ограничитель читает этот топик.

- **Автопилот / обработчик миссий**:
  - Пишут миссию (либо в `agrodron.autopilot.mission`, либо в `agrodron.limiter.mission`, если сделаете отдельный поток).

- **Приводы (мотора)**:
  - Пишут своё состояние в `agrodron.motors.state`.

- **Опрыскиватель**:
  - Пишет своё состояние в `agrodron.sprayer.state`.

- **Ограничитель**:
  - Подписывается на все перечисленные топики.
  - Пишет результаты анализа в `agrodron.limiter.event` и, при необходимости, в `agrodron.limiter.state`.

Такое ТЗ даёт разработчикам других компонентов понятный протокол взаимодействия с ограничителем и оставляет свободу реализации внутреннего алгоритма анализа (можно начать с простого порога по расстоянию и высоте, а затем усложнять).
